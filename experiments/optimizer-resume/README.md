# CPU-offloaded optimizer checkpoint resume

This unit restores Python parameter-group metadata after DCP loads optimizer tensors directly into their existing CPU buffers. The saved learning rates, group options and Muon group step counters apply to each base optimizer in the original group order. Parameter objects and state tensor storage are retained. A template snapshot of canonical parameter names rejects group count/order/membership mismatches before applying metadata. The checks validate the groups DCP presents against its current template; they do not inspect checkpoint entries omitted by DCP or promise compatibility with a changed optimizer configuration. No optimizer algorithm, schedule, precision or offload configuration changes.

The shared `AppState` path serves actor, SFT and independent value training. The change adapts upstream `91dce1f3`; it does not replace the existing offload wrapper or checkpoint format.

## Acceptance

`tests/integration/optimizer_resume_probe.py` uses actual single-rank DCP and CPUOffloadOptimizer with an FP32 MLP. It checkpoints after three updates, verifies loaded full model/optimizer state and CPU-buffer/parameter identity, then compares two continued updates including full gradients against uninterrupted training. Cases cover actual Dion Muon, an AdamW positive control, and two mixed wrapped/unwrapped optimizers with distinct group metadata. Frozen Muon must expose reset group counters and actual continuation divergence; candidate continuation must match exactly. Candidate-only malformed-group controls reject rather than silently remap metadata.

The probe requires the existing GPU environment, uses no new dependencies and makes no full-model/FSDP repartition or throughput claim. Both expected-outcome GPU stages exited normally. The frozen Muon and mixed-optimizer controls restored group steps as `[1, 1]` instead of the saved `[3, 3]`, and the continued model updates diverged. The unchanged Adam control resumed exactly. The candidate restored complete metadata and tensor state and matched both uninterrupted continuation updates exactly for all three cases, including complete gradients. Count/order/membership corruption was rejected before changing model/group state or initializing wrappers.

The parent independently verified all 43 archive members, 333 runtime source/config/test hashes, all three applied paths and the saved numerical states. One additional source differs only by the separately committed Rollout docstring; its frozen hash and executable AST identity were checked. Saved/loaded tensor counts were 10 for Muon, 16 for Adam and 13 for mixed optimizers; two-update comparison counts were 30, 42 and 36 respectively. Non-tensor metadata was compared too. These are bounded actual checkpoint comparisons, not a full-model or FSDP resharding result.

Raw evidence: `prime-values-shared:/data/optimizer-resume-001/evidence.tar.gz`, 415,032 bytes, SHA256 `9fdb34af2b77727f6c3413f548191cb9abfcbf5796eab5f2496d4aa365100b4a`. Includes numerical states, actual DCP checkpoint files and logs. The existing shared GPU job was reused. Earlier default-Adam validation remains applicable; this regression concerns metadata omitted by the CPU-offload loading path.
