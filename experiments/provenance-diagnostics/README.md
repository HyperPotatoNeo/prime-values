# Sampled policy-version diagnostics

This unit adds detached observations beside existing trainer token metrics. The backend prerequisite passed its actual fresh/resume and generated weight-span gates. The diagnostics passed focused CPU/distributed checks and an actual frozen one-update actor comparison.

The population is exactly the existing returned mismatch mask: loss-masked tokens with RL or reference-KL membership, retaining the existing absent-component fallback. CE-only tokens, padding, dummy tokens and deduplicated shared-prefix tokens stay outside this denominator. Provenance follows the physical input-token axis and is never shifted with logits.

`observed_policy_version/` reports eligible, known and unknown counts and fractions. In a single run without LoRA, the forward for optimizer step `t` uses version `t-1`; future labels are counted separately. `sampled_weight_age/` reports count, mean and maximum only for known nonfuture labels. Unknown is not version zero, future versions are not clamped into age zero, and zero eligible tokens have no defined fraction. All-unknown populations have known fraction zero and no age mean/max. Multi-run or LoRA configurations report coverage only, without claiming a comparable version namespace.

The carrier is already validated by the accepted transport decoder. Its dtype and physical shape are checked here. Comparisons and subtraction occur in int64 before conversion to the existing FP64 summary reducer; `where` removes invalid age operands before subtraction. FP64 mean/max are ordinary diagnostic summaries and cannot represent every enormous int64 age exactly. Raw exact label spans remain in the original trace. Neither these metrics nor engine labels describe dispatch age, the full history of cached KV context, or critic versions.

CP ranks receive duplicated full token arrays after gathering. Only CP rank zero contributes observations; every rank still joins the normal global reduction. Counts are summed before computing fractions, so unequal rank populations are token-weighted. No loss, scale, precision, mask, admission, value-owned data or optimizer setting changes.
