# Streaming entropy and mismatch telemetry

This unit adapts the GPU metric-accumulation principle from upstream `1bdf9d6635c66e4df89a18985a9e38b1fe4947bc` to the existing value-safe trainer. It changes only standard per-token entropy and mismatch telemetry plus lazy microstep debug formatting. Scalar, sample and custom loss metrics still use the existing collector, including its medians. Policy/value objectives, normalization, optimizer precision and context-parallel replication are unchanged.

`TensorSummaries` keeps its default count/mean/min/max behavior for ratio-tail diagnostics. The opt-in standard stream adds centered sample variance (correction 1), combines centered moments across ranks, and explicitly propagates valid NaNs into extrema. Masked entries are excluded before arithmetic; opposing infinities remain visible. Empty standard entropy remains present with NaN statistics; globally absent mismatch remains absent. Existing context-parallel duplicate observations remain duplicated, including their effect on sample standard deviation.

The standard stream stops retaining raw per-token arrays and computing medians. The trainer's existing monitor filter already omits entropy/mismatch medians, so this does not remove a currently emitted monitor series. This is not a claim that all trainer metrics are streamed, that the trainer is free of host synchronization, or that training throughput improves.

## Acceptance evidence

- `tests/unit/train/test_tensor_summaries.py` and `tests/unit/train/rl/test_token_metrics.py`: 7 focused CPU cases passed. Independent actual policy-loss instrumentation control compares full parameter gradients and an AdamW update exactly; masked mixed-component inputs exercise eligibility.
- `tests/integration/token_metrics_probe.py`: 8 cases passed with two Gloo ranks, independently gathering observations as the oracle. Covers unequal populations/environments, an all-masked rank, duplicated CP observations, all-empty visibility, NaN on either rank, opposing infinities and high-offset centered variance. The same script targets NCCL/CUDA. Receipts guard and hash actual imported sources.
- `tests/integration/metric_trainer_smoke.py`: passed frozen-first execution of one actual trainer update with its supported fake-data source and normal FP32 optimizer/reductions. Requires a nonzero update, exact exported BF16 weights and matching filtered tensor telemetry. This export comparison does not prove full FP32 optimizer-state identity. CPU instrumentation tests separately compare gradients and optimizer updates. If exact GPU exports differ, first check frozen repeatability; do not loosen tolerances to accept a candidate.
- `tests/integration/profile_token_metrics.py`: profiled the actual extracted frozen accumulation block against the streaming helper, including the new environment-ID upload and unchanged scalar-loss CPU copy. Reports CUDA copy/sync events and retained data sizes. Excludes end-step collectives, debug formatting and the model; it is not a throughput benchmark.

All four GPU stages exited normally with status 0. The actual trainer changed nine parameters; its 12 exported BF16 tensors matched exactly and 107 filtered metrics matched within the predefined 1e-12 tolerance. The same eight distributed cases passed with two CUDA/NCCL ranks. The profiler's three 65,536-token accumulation rounds reduced retained host elements from 524,283 to 3 and device-to-host copy events from 27 to 3; 54 summary elements remained on device. Scalar copies remain, and some device operations increase. No whole-step speed or reward improvement is established.

The parent independently verified 59 archive member hashes, 334 runtime source/config/test hashes against the integration tree, the actual paired checkpoint tensors, nonzero updates and filtered metrics. The source-review receipts retain their original pre-GPU status; the later runtime and parent receipts close those gates. No dependency, policy/value objective or precision change is included.
