# Next producer and dependency migration

The current-stack synchronization milestone ends with exact-order packing refinement (`3a54a7bf`). Its baseline, safety, owned critic trajectories, canonical Episodes, native task ownership, explicit attention boundaries, streamed metrics, parameter-safe offload and optimizer resume fixes have separate acceptance records. This is selective upstream adoption, not parity with latest Prime RL.

The completed [native RG unit](../native-rg/README.md) adds native RG tasks alongside the existing legacy package on the current verifier `b13ba60d`, renderer `bdb96b0c` and vLLM 0.24 stack. This clean package boundary removes one actual dependency on the legacy bridge without changing existing experiments, objectives or inference backends. See the [concrete native RG plan](native-rg-first-unit.json). The original untracked RG source and cached dataset were frozen by observed hashes before implementation. Exact dataset order, system/question prompts, answer-parser quirks and deterministic scoring remain the reference. Private scorer metadata must never become model context or a value prefix.

Completed acceptance compares all 10,256 saved rows and real scorer/parser behavior, two actual worker processes, exact renderer requests and policy arrays, and actual TrainSink value credit/publication in task and leave-one-out modes. The installed wheel also preserves both entrypoints. A repeated GPU training grid is not justified for a package-only change with unchanged requests; any discovered renderer/request change must be verified at that boundary first.

The [environment inventory](environment-inventory.json) distinguishes 78 scanned configuration files and 88 declared entries from actual saved research runs. It includes 69 legacy and 19 native entries. Porting RG alone does not authorize deleting legacy support: reverse-text, math and other example families still depend on it, and group-scored environments need equivalent group semantics.

The [dependency audit](value-boundary-review.json) establishes that the later verifier removes the legacy bridge, adopts streamed Episode assembly, changes error fields and distinguishes logical renderer IDs from physical token IDs. The renderer also changes reasoning/prefix behavior. These are real compatibility boundaries. Migrate them in coherent units before adding exact sampled-token policy versions and staleness-binned diagnostics; never substitute group-dispatch ages for token versions. Preserve existing cancellation, value publication, independent GAE/TD lambdas, TETHER timing and optimizer/reduction precision.

The [remaining current-stack review](current-stack-roadmap.json) separately records large-evaluation event-loop and GC scheduling opportunities. Those need representative workload and lifecycle evidence; the small validation runs do not establish those bottlenecks. Score centering and EMA KL belong to the separate research branch and must not be duplicated here.

The [sequence-boundary unit](../sequence-boundary/README.md) now provides an explicit, opt-in single-turn training projection. Its real producer/sink acceptance preserves legacy clipped token geometry and covered critic/filter behavior while keeping native defaults and original physical traces intact. Bulk example rewrites remain deferred. Native math differs in datasets, parser strictness and grading safeguards; it is not a drop-in replacement.

The [next producer/backend roadmap](native-next-roadmap/README.md) identifies the minimum coherent dependency pair, physical-token and streamed-Episode boundaries, and later real mixed-version inference gate. Existing legacy configurations must not be silently mapped to different native tasks.
