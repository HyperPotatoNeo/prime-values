# Next producer and dependency migration

The current-stack synchronization milestone ends with exact-order packing refinement (`3a54a7bf`). Its baseline, safety, owned critic trajectories, canonical Episodes, native task ownership, explicit attention boundaries, streamed metrics, parameter-safe offload and optimizer resume fixes have separate acceptance records. This is selective upstream adoption, not parity with latest Prime RL.

The next implementation unit adds native RG tasks alongside the existing legacy package on the current verifier `b13ba60d`, renderer `bdb96b0c` and vLLM 0.24 stack. This clean package boundary removes one actual dependency on the legacy bridge without changing existing experiments, objectives or inference backends. See the [concrete native RG plan](native-rg-first-unit.json). The original RG source is locally untracked; its observed bytes and the cached dataset must be frozen before implementation. Exact dataset order, system/question prompts, answer-parser quirks and deterministic scoring remain the reference. Private scorer metadata must never become model context or a value prefix.

Acceptance will compare frozen/native dataset and reward behavior, run real two-worker task reconstruction and Episode serialization, and compare the actual value-owned materialization and private prompts. A repeated GPU training grid is not justified for a package-only change with unchanged requests; any discovered renderer/request change must be verified at that boundary first.

The [environment inventory](environment-inventory.json) distinguishes 78 scanned configuration files and 88 declared entries from actual saved research runs. It includes 69 legacy and 19 native entries. Porting RG alone does not authorize deleting legacy support: reverse-text, math and other example families still depend on it, and group-scored environments need equivalent group semantics.

The [dependency audit](value-boundary-review.json) establishes that the later verifier removes the legacy bridge, adopts streamed Episode assembly, changes error fields and distinguishes logical renderer IDs from physical token IDs. The renderer also changes reasoning/prefix behavior. These are real compatibility boundaries. Migrate them in coherent units before adding exact sampled-token policy versions and staleness-binned diagnostics; never substitute group-dispatch ages for token versions. Preserve existing cancellation, value publication, independent GAE/TD lambdas, TETHER timing and optimizer/reduction precision.

The [remaining current-stack review](current-stack-roadmap.json) separately records large-evaluation event-loop and GC scheduling opportunities. Those need representative workload and lifecycle evidence; the small validation runs do not establish those bottlenecks. Score centering and EMA KL belong to the separate research branch and must not be duplicated here.
